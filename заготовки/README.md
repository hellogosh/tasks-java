# Заготовки

Код, который на занятии дается готовым: его проверяем, а не пишем. Скопируйте файлы нужного модуля в `src/main/java/training/tracker/` в начале занятия.

| Папка | Модуль | Классы |
|---|---|---|
| `02` | Бизнес-правила и граничные значения | `ProjectCodeValidator` |
| `03` | Параметризация и тест-дизайн | `PermissionService` |
| `04` | Тестовые данные и коллекции | `TaskFilter`, `StatusDictionary`, `StatusCounter` |
| `07` | Файлы и диагностика падений | `TaskWorkflow`, `TaskFileReader`, `TaskLineParser` |
| `06-если-не-успели` | запасной вариант к модулю 7 | `Task`, `TaskStatus`, `Priority`, `TaskService`, `User` → `src/main/java/training/tracker/`; `builders/TaskBuilder` → `src/test/java/training/tracker/builders/`; `tests/` — тесты модуля 5 на enum → `src/test/java/training/tracker/` |

Классы `Task`, `TaskStatus`, `Priority`, `TaskService`, `TaskBuilder`, `TaskResponse` и остальные вы пишете сами на занятиях 5, 6 и 9. Заготовки модуля 7 рассчитаны на `Task` с `TaskStatus` и `Priority`; тесты модуля 7 пишутся через `TaskBuilder` из модуля 6. Если на шестом занятии не успели — возьмите их из `06-если-не-успели`, но сначала попробуйте дописать свои: это решение задач модуля 6.

### Если берёте `06-если-не-успели`

Это согласованный комплект: модели (`Task` уже с `isOpen()` и `withStatus(...)` из модуля 5), `TaskService` на `TaskStatus`, `TaskBuilder` и тесты модуля 5, переведённые на enum со всеми проверками.

1. Скопируйте `Task`, `TaskStatus`, `Priority`, `TaskService` в `src/main/java/training/tracker/` (и `User`, если своего record из модуля 5 нет — он нужен `tests/TaskModelTest`), `builders/TaskBuilder` — в `src/test/java/training/tracker/builders/`. Свои дополнительные методы `TaskService`, если были, перенесите в скопированный.
2. Свои тесты модуля 5 переведите сами: `"OPEN"` → `TaskStatus.OPEN`, `"HIGH"` → `Priority.HIGH`. Не успеваете — замените свой класс одноимённым из `tests/`.
3. Проверки не удаляйте и не комментируйте. Если класс пришлось временно отключить — это незавершённая работа: запишите его в список «вернуть» и скажите тренеру.
4. Запустите `./gradlew test` — сборка зелёная, тестов не меньше, чем до миграции. Так должно быть до начала модуля 7.

До модуля 8 модели и сервисы (production-код) лежат в корневом пакете `training.tracker`; отдельные пакеты с самого начала есть только у `stub`, `environment`, а с модуля 6 — у `builders` и `assertions`. На восьмом занятии разложим остальное по пакетам.

Все классы пакета `training.tracker.stub` (учебный стаб трекера) нужны для модулей 9 и 10. Их не трогаем. Пакет `training.tracker.environment` — проверка окружения перед курсом (`EnvironmentSmokeTest`, `BrowserSmokeTest`), его тоже не переносим.

## Для тренера: контрольные точки

Если пара отстала сильнее, чем на один модуль, проверенные состояния проекта после модулей 03, 05, 06, 08 и 09 лежат в `Материалы для тренера/Контрольные точки/` (участникам не выдаются целиком — тренер копирует недостающие файлы текущего модуля). Порядок действий — в README этой папки.
