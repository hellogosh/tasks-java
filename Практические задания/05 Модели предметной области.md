# Практическое задание 05. Модели предметной области

## Цель

Заменить отдельные строки моделью `Task` на record и проверять объекты целиком и по полям.

## Стартовая точка

Работайте в `starter-project`, в пакете `training.tracker`. Заготовок в этом модуле нет: модель и сервис вы пишете сами. Разбор строки файла в `Task` — в модуле 7, здесь объекты создаются в коде теста.

## Разминка

Без подсказок напишите в новом классе `TaskFilterWarmupTest` два теста на `TaskFilter.byStatus` из модуля 4: из `List.of("OPEN", "DONE", "OPEN")` по статусу `OPEN` возвращается `List.of("OPEN", "OPEN")`, по `CANCELLED` — пустой список. Класс новый: в `TaskFilterTest` уже есть похожие методы.

## База

### Задание 0. Класс `Task` с методами

Вместе с тренером напишите обычный класс `Task` в `src/main/java/training/tracker/Task.java`: поля `key`, `title`, `status`, `priority` (`private final`), конструктор с четырьмя параметрами и методы доступа `key()`, `title()`, `status()`, `priority()`.

Дальше — самостоятельно:

- метод `boolean isOpen()` — `true`, если статус `OPEN`; тесты на оба исхода;
- метод `Task withStatus(String newStatus)` — возвращает **новую** задачу с другим статусом; тест проверяет новую задачу и то, что исходная не изменилась;
- сравните через `assertEquals` две задачи с одинаковыми полями. Тест упадет — объясните почему.

Конструктор ничего не проверяет: он только заполняет поля. Правила для полей модели в курсе не нужны.

### Задание 1. Перевести `Task` на record

Делаем вместе с тренером в блоке 4. Если не успели — закончите перед заданием 2.

```java
public record Task(String key, String title, String status, String priority) {
}
```

Методы `isOpen()` и `withStatus(...)` перенесите в тело record. Тесты задания 0 должны остаться зелеными, а тест на две одинаковые задачи — позеленеть.

### Задание 2. Написать фильтр

Создайте `TaskService` с методом:

```java
public List<Task> tasksWithStatus(List<Task> tasks, String requiredStatus)
```

Метод возвращает только задачи с нужным статусом.

### Задание 3. Написать тесты

Напишите `TaskServiceTest`:

- возвращаются только задачи с нужным статусом — сравнение списков объектов через `assertEquals`;
- если совпадений нет, возвращается пустой список;
- у найденной задачи сохраняются все поля — `assertAll` по `key`, `title`, `status`, `priority`.

### Задание 4. Factory method

Вынесите создание задачи в factory method теста: `private Task task(String key, String status)`. Делаем вместе с тренером в блоке 6.

## Практика+

Для тех, кто закончил задание 3 раньше времени.

- Вспомогательный метод теста `private int countOpen(List<Task> tasks)`: цикл, счетчик, `isOpen()` в условии; тесты — две открытые задачи из трех и пустой список.
- Свой record: `public record User(String login, String name)` и тест — два пользователя с одинаковыми полями равны, с разным `login` не равны (`assertNotEquals`).
- Тест, который не может упасть: если где-то проверяется только `result.size()`, временно сломайте `TaskService`, чтобы он возвращал неправильные задачи того же количества. Тест останется зеленым — замените проверку на сравнение состава и убедитесь, что теперь он красный. Верните сервис.
- Напишите вариант `Task` как обычный класс без `equals`: сколько кода экономит record?
- Добавьте в `TaskService` метод `List<Task> openTasks(List<Task> tasks)` на основе `isOpen()` и тест к нему.

## Challenge

Добавьте в класс-вариант `Task` методы `equals` и `hashCode` (IDE: *Generate*) и проверьте, что ловушка из задания 0 исчезла.

## Выходная мини-задача

Без подсказок: две задачи `OPEN` с разными приоритетами и одна `DONE` — фильтр по `OPEN` возвращает обе открытые задачи в исходном порядке.

## Команды проверки

```bash
./gradlew test
```

## Критерии приемки

- Создан record `Task` из 4 полей с методами `isOpen()` и `withStatus(...)`, на оба метода есть тесты.
- `TaskService.tasksWithStatus` используется в production-коде и в тестах.
- Проверено несколько полей объекта; ни один тест фильтра не опирается только на `size()`.
- Участник объясняет, почему сравнение объектов зависит от `equals`.
- Все тесты проходят через `./gradlew test`.
