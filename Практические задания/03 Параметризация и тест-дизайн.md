# Практическое задание 03. Параметризация и тест-дизайн

## Цель

Перевести таблицы тест-кейсов в параметризованные JUnit-тесты и убрать дублирование.

## Стартовая точка

Работайте в `starter-project`. Скопируйте заготовку модуля:

- `заготовки/03/PermissionService.java` → `src/main/java/training/tracker/`

`ProjectCodeValidator` и его тесты остаются с прошлого занятия.

## Исходное требование

```text
Редактировать задачу могут роли ADMIN, MANAGER и TESTER.
VIEWER редактировать задачу не может.
Неизвестная, пустая или отсутствующая роль не дает права редактирования.
```

## Разминка (начало занятия, 8 минут, затем разбор решения)

```text
Оценка задачи в часах валидна, если она больше 0 и не больше 160.
```

Сами создайте класс `EstimateValidator` в `src/main/java/training/tracker/` с методом `boolean isValid(int hours)` — это ваш первый метод без заготовки. Напишите два обычных `@Test` на границы: `0` — невалидно, `160` — валидно. Остальные значения добавите в задании 2.

## База

Обязательный результат — **не менее 3 параметризованных методов**, среди них обязательно: длина кода, `EstimateValidator`, роли с `null` через `@MethodSource`, — и отдельный тест на `null` для кода проекта. CSV-тест ролей из задания 3 остаётся, поэтому после задания 4 методов будет четыре — это правильно. Параметризованный метод с пятью строками данных — это один метод и пять запусков.

### Задание 1. Переписать тесты на `@CsvSource`

Возьмите тесты для `ProjectCodeValidator` из прошлого модуля и объедините проверки длины в один параметризованный тест `ProjectCodeValidatorParameterizedTest`:

| code | expected |
|---|---|
| `''` | false |
| `Q` | false |
| `QA` | true |
| `PROJECT123` | true |
| `PROJECT1234` | false |

Тест на `null` из прошлого модуля **не удаляйте**: в эту таблицу он не входит. После рефакторинга сценариев должно быть не меньше, чем до.

### Задание 2. Параметризовать свою функцию

Два теста `EstimateValidator` из разминки сверните в один тест с `@CsvSource` (`hours, expectedValid`) и добавьте строки для `-1`, `1`, `161` — всего пять строк.

### Рефакторинг своих тестов (после задания 2)

В своих `ProjectCodeValidatorTest` и тесте `EstimateValidator`:

- создание объекта — в поле класса или `@BeforeEach`;
- повторяющуюся проверку с одинаковым сообщением — в helper-метод, если такая есть;
- в каждом тесте остаются вход, действие и проверка.

Готово, когда всё зелёное, а число сценариев не уменьшилось.

### Задание 3. Покрыть права ролей

Напишите `PermissionServiceTest` с параметризованным тестом на `@CsvSource`. Сервис создайте в поле класса или в методе с `@BeforeEach`.

| role | expected |
|---|---|
| ADMIN | true |
| MANAGER | true |
| TESTER | true |
| VIEWER | false |
| UNKNOWN | false |

### Задание 4. Добавить null-case

Создайте **новый класс** `PermissionServiceMethodSourceTest`: те же случаи плюс `null` через `@MethodSource` и `Arguments.of(...)`. Метод-источник — `static`. `PermissionServiceTest` из задания 3 не удаляйте и не меняйте.

### Выходная задача — в конце занятия

Слайды закрыты. Параметризованный тест для `PermissionService` по новой таблице: `admin` → false, `" ADMIN"` → false, `TESTER` → true, `VIEWER` → false. Подумайте, как записать в таблице значение с пробелом в начале.

## Практика+

- Напишите `PermissionServiceInvalidInputTest` с `@NullSource` и `@EmptySource`.
- Добавьте тест на `@ValueSource(strings = {"ADMIN", "MANAGER", "TESTER"})` с сообщением `role + " должен иметь право редактировать задачу"`.
- Перепишите SLA-тесты первой встречи в один тест с `@CsvSource`: приоритет и ожидаемые часы.

## Challenge

Добавьте параметризованный тест для допустимых символов кода проекта (`"QA1"`, `"Qa"`, `"QA-1"`, `"1QA"`, `"Q_A"`; `"qa"` — дополнительной строкой, он нарушает два условия) и дайте каждому случаю читаемое имя через `@ParameterizedTest(name = "...")`.

## Команды проверки

```bash
./gradlew test
```

## Критерии приемки

- `EstimateValidator` написан самостоятельно, его тесты свёрнуты в `@CsvSource`.
- Не менее 3 параметризованных методов, среди них: длина кода, `EstimateValidator`, роли с `null` через `@MethodSource`. Четыре метода (с CSV-тестом ролей) — тоже верно.
- Тест на `null` для кода проекта сохранён.
- Общая подготовка вынесена в поле класса или `@BeforeEach`.
- Все тесты проходят через `./gradlew test`.
